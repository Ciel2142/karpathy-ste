What is in the file?

The page is one HTML file. It has no remote parts, thus it opens offline from one file.

Then the file has these parts, in this sequence:

  1. The head contains guard part 1, the rung meta, the title and the style.
  2. The body contains the header, the navigation bar, one section for each facet and the footer.
  3. Two scripts close the body: the steps player and guard part 2.

  • Cite each claim about a file.
  • Write all prose in STE-80. ASD-STE100 "Simplified Technical English"

How do you show code?

Put each code block in a figure.code element. The caption gives the source as name:line, and the pre element contains the lines.

Copy the lines from the source without a change. Write each < as &lt; and each > as &gt;.

How do you hide a long walkthrough?

Put a long explanation in a details.walk element. The summary is a question. The reader opens the element to read the answer.

What does the guard do with a details element?

With #verify in the URL, the guard opens each details element. Thus the screenshots show all the text, and the guard measures all the text.

When do you use a details element?

Use it for a long proof, a full list or a second example. Keep the main answer outside it.

Which diagrams can you draw?

The template has three diagram patterns in inline SVG. Copy the pattern that agrees with the shape of your subject. Then change the labels.

Each SVG has a viewBox of 600 units in width, role="img" and a title. The text is 18 units high, thus it stays at 14 px or more on a narrow screen.

Flow

Each box is a rect and a text. Each arrow is a line with marker-end. The marker in defs draws the arrowhead.

Sequence

Each participant has a box and a dashed lifeline. Each message is an arrow between two lifelines, with a number.

Layers

Each layer is one band: a rect with a text. The top band is the layer that the reader sees.

How does the steps player work?

The player shows one step at a time. Each step has its own diagram and caption. The buttons go to the previous step or to the next step.

With #verify in the URL, the guard shows all the steps, one below the other.

What does the guard check?

The guard is two scripts. Part 1 is the first script in the head, and it counts script errors. Part 2 runs one time, in the load event.

StatusCause
HSCROLLThe page is wider than the window.
SMALLTEXT:<px>Some text is smaller than 14 px.
JSERRORA script error occurred.
OKNo check failed.

The guard writes the result into data-verify on the html element. verify.sh loads the page at 1440 px and at 500 px, and reads this attribute. The guard does not change the page title.

Where does the page show its source?

The footer shows the subject, the source, the date, the commit and the dirty flag. cite_check.py uses data-root to find each cited file.

The last line of the footer lists each facet that the page does not explain, for any reason.
